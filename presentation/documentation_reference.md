# Documentation Reference

## Purpose

The documentation is the primary technical source of truth.

Its purpose is not to copy text into slides.

Its purpose is to discover:

- engineering decisions
- implementation details
- diagrams
- benchmarks
- trade-offs
- lessons learned
- testing
- architecture

---

# Reading Strategy

When reading documentation,

identify:

- what is presentation-worthy
- what should remain documentation-only
- what deserves diagrams
- what deserves benchmarks
- what deserves speaker notes

---

# Extraction Priorities

Highest Priority

- engineering decisions

- architectural choices

- performance optimizations

- security

- trade-offs

- scalability

- interesting implementation details

Medium Priority

- APIs

- package choices

- algorithms

- testing

Lower Priority

- UI descriptions

- repeated explanations

- boilerplate implementation

---

# Slide Selection

Not every documentation section deserves a slide.

Evaluate:

- Is this memorable?

- Does this demonstrate engineering?

- Will an examiner ask about it?

- Does it strengthen the story?

Only include topics that improve the presentation.

---

# Simplification

The presentation should explain,

not duplicate.

Convert documentation into:

- diagrams

- timelines

- workflows

- comparisons

- short bullets

Move detailed explanations into speaker notes.

---

# Engineering Storytelling

When possible,

convert

Implementation

↓

into

Problem

↓

Constraint

↓

Decision

↓

Implementation

↓

Trade-off

↓

Result

---

# Missing Opportunities

While reading,

identify:

- missing diagrams

- missing screenshots

- missing benchmarks

- missing explanations

- possible demonstrations

---

# Questions

Whenever the documentation is unclear,

ask before making assumptions.

Never invent missing technical details.

---

# Final Review

Before creating slides,

verify that:

- all engineering highlights have been considered

- the presentation is consistent with the documentation

- no important technical achievement has been overlooked
